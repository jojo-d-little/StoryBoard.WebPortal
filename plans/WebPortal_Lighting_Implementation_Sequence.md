# WebPortal lighting: implementation sequence

Use the [detailed plan](WebPortal_Lighting_Detailed_Implementation_Plan.md) for field mappings, ownership rules, transition behavior, and acceptance checks. The [newer Host handoff](LIGHTING_WEBPORTAL_HANDOFF.md) takes precedence over the older portal plan where they differ.

1. **Prepare dependencies and contracts.** The contracts dependency is already pinned to `1.0.6`. Verify an approved published Lighting package version, install it, and update WebPortal's local Host TypeScript definitions from the staged generated interfaces. Keep the current local interface approach.
2. **Retain complete Host lighting state.** Carry session cell size and project defaults through baseline, resync, and deltas. Replace room state on every `newRoom`, even for the same room ID. Track each object's light, footprint, and occlusion before filtering image-free objects from visual rendering. Apply object changes as complete replacements.
3. **Create a pure mapping boundary.** Add renderer-neutral lighting data to `GameRenderSceneSnapshot`. Map room pixels, effective ambient, current point lights, and blockers to package inputs. Preserve zero values, clear removed entries, and keep all viewport and sprite coordinates out. Add focused state/mapping tests.
4. **Add one Pixi lighting controller.** After Pixi WebGL initialization, create a borrowed room-size source texture and the package pipeline. Each enabled frame captures the current room surface, submits the complete lighting frame, renders with absolute seconds, and presents the composed texture. The disabled or failed path presents the existing raw surface.
5. **Wire the live Devtools switch.** Add a catalog-independent Lighting checkbox in Presentation Effects, initially off for rollout. The master visual-effects switch also suppresses it. Put the effective `if` at the normal room-presentation seam so off skips capture and package calls.
6. **Complete movement and transitions.** Interpolate object-owned light positions from Host before/after endpoints during presentation tweens; switch blocker cells at leg boundaries. Feed final lit/raw room images to bounded transition captures. Use one pipeline and frozen final images when both outgoing and incoming rooms must appear at once.
7. **Add the grid diagnostic and verify in the browser.** Add the separate, initially-off room-grid Devtools control from the detailed plan. Test ambient-only rooms, light-only objects, blockers and explicit zero, same-room phase changes, object removal, older projects, room swaps, live toggling, viewport resize, and failure/disposal paths. Run build, unit, and visual suites; measure representative GPU cost before changing the lighting default to on.
